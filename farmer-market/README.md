# 청년농부 장터 화면 미리보기

4단계 회원 인증을 연결한 로컬 개발 앱. 회원가입·이메일 확인·로그인·로그아웃·비밀번호 재설정은 서버와 SQLite를 사용한다. 모든 상품·농장·가격·재고·배송비·일정은 예시이며 실제 판매·결제·문의 접수·이메일 발송은 연결하지 않았다.

## 실행

### 최신 회원 기능 미리보기

```powershell
node farmer-market/server.cjs --dev-mailbox
```

[로그인](http://127.0.0.1:4175/#login) · [회원가입](http://127.0.0.1:4175/#register) · [로컬 테스트 수신함](http://127.0.0.1:4175/#mailbox)

가상 이메일과 시험용 비밀번호로 가입→수신함의 확인 링크→확인 버튼→로그인을 시험한다. 비밀번호 재설정도 로컬 수신함을 사용한다. 실제 이메일은 보내지 않는다. `--dev-mailbox`를 생략하면 수신함과 메일 의존 가입/재설정은 비활성화된다. 이전 4173 대신 최신 통합 앱은 **4175**에서 제공한다.

회원·세션은 DB 저장, 상품·소개·장바구니는 여전히 예시/로컬 저장이다. 농부 관리는 서버 운영자 권한 확인 후 화면을 연다. 확인 완료한 본인의 시험 계정은 `node farmer-market/backend/admin.cjs test@example.invalid`로 운영자 권한을 부여하고 다시 로그인할 수 있다. 기본 관리자 비밀번호는 없다. 자세한 범위와 제한은 [4단계 안내](../docs/04-auth-implementation.md)를 따른다.

### 3단계 서버·DB 기반

[기술·인증 설계](../docs/03-architecture.md) · [DB 모델](../docs/03-data-model.md) · [API 명세](../docs/03-api-spec.md)

프로젝트 루트에서 다음 명령으로 DB와 읽기 API를 시험한다. 외부 패키지 설치는 필요 없다.

```powershell
node farmer-market/backend/database.cjs --seed-demo
node farmer-market/backend/dev-server.cjs
```

API 서버 실행 중 [상태 확인](http://127.0.0.1:4174/api/health), [농부 목록](http://127.0.0.1:4174/api/v1/farmers), [상품 목록](http://127.0.0.1:4174/api/v1/products)을 볼 수 있다. DB는 웹 폴더 밖 `.farmer-market-data/market.sqlite`에 저장되며 기존 레코드는 시드 반복 실행으로 덮어쓰지 않는다.

```powershell
node farmer-market/backend/verify.cjs
```

전체 구문·상품·농부·DB/API 검증은 `node farmer-market/verify-all.cjs`로 실행한다. 현재 환경에는 npm이 없으므로 Node 명령을 사용한다.

검증은 별도의 메모리 DB와 임시 포트를 사용한다. 실제 DB·브라우저 저장 데이터·계정은 변경하지 않는다. 이 4174 서버는 3단계 공개 목록 API이며 인증 화면은 위 최신 4175 통합 앱으로 시험한다. 실제 메일·결제는 미구현이다.

### 기존 화면 미리보기

프로젝트 루트에서 실행한다. Node.js 외 추가 패키지는 필요 없다.

```powershell
node farmer-market/server.cjs
```

브라우저에서 [미리보기](http://127.0.0.1:4175)를 연다. 종료는 실행 터미널에서 `Ctrl+C`를 누른다. 서버를 종료했을 때는 위 명령으로 다시 실행한다. 외부 공개 없이 같은 컴퓨터에서만 접속한다.

## 시험할 수 있는 기능

- 홈·농부 소개·이야기·대량구매·고객센터 화면 이동.
- 상품명 검색, 채소/과일 필터, 농부별 필터와 검색 결과 없음 안내.
- 상세 수량 선택·재고 제한·품절/수확 예정의 알림 안내 화면.
- 장바구니 추가·수량 변경·삭제·브라우저 새로고침 후 저장 유지.
- 농부별 상품 묶음·배송비·무료배송 기준·전체 합계 계산.
- 주문서 화면과 회원/비회원 구매 안내 전환.
- FAQ 펼치기와 개인정보 입력 없는 견적 접수 결과 예시.

장바구니는 이 브라우저의 로컬 저장소에만 저장한다. 실제 개인정보는 입력받지 않는다. ‘알림 화면 보기’는 안내만 제공하며 신청이 아니다.

## 계산 검증

```powershell
node farmer-market/verify.cjs
```

| 시나리오 | 기대 결과 |
|---|---|
| 사과 1 + 고구마 1 (다른 농부) | 상품 42,000원 + 배송 7,500원 = 49,500원 |
| 고구마 1 + 배추 1 (같은 농부) | 배송 묶음 1개, 상품 34,000원 + 배송 4,000원 = 38,000원 |
| 사과 3 + 고구마 1 | 사과 농장 무료배송, 총 94,000원 |
| 품절 배·수확 예정 당근·없는 상품·음수/소수 수량 | 저장 장바구니 정규화 시 제외 |
| 동일 상품 중복·과다 수량 | 합산 후 재고 상한 적용 |

## 검증 기록

### 회원 인증 (2026-11-10)

- `backend/verify-auth.cjs`에서 가입·해시·동의·역할 주입 차단·확인/재설정 토큰·세션 분리/만료·로그아웃·CSRF/Origin·권한·시도 제한·수신함 비활성화를 검증했다.
- 전체 실행: `node farmer-market/verify-all.cjs`. 기존 농부·상품·배송비·DB/API 검증도 함께 통과했다.
- 브라우저에서 가상 주소 계정의 가입·이메일 확인·로그인·새로고침 유지·관리자 접근 차단·로그아웃을 확인했다. 모바일 360px 화면도 점검했다.

### 홈 상품 페이징 (2026-11-10)

- 홈 상품 구획에 전체 개수·표시 범위·이전/다음·페이지 번호를 추가했다. 상품 4개씩 표시하며 현재 13개는 4페이지다.
- 농부 소개의 3곳씩 넘기기와 별도로 동작하며, 현재 상품 페이지에서 상세 보기·장바구니 담기를 이용한다.
- 첫/끝 페이지의 이전/다음 버튼 비활성화, 마지막 페이지의 13번째 상품, 이전 페이지 4개 복귀를 브라우저에서 확인했다.
- 페이지 이동 시 상품 구획으로 스크롤하고 선택된 페이지 버튼으로 키보드 초점을 옮긴다. 새로고침하면 첫 페이지부터 표시한다.

### 장터와 농부 데이터 통일 (2026-11-10)

장터 농부 필터·상품 카드·상세·장바구니·주문서와 농부 소개의 판매 상품을 공통 ID로 연결했다. 소개 기본 데이터도 `domain.js`의 농부 목록에서 생성하여 이름·지역·작물의 중복 정의를 줄였다. 직접 수정한 로컬 소개는 보존한다.

| 농부 | 지역 | 취급 상품 |
|---|---|---|
| 예시1 | 경북 영주 | 사과, 배(품절) |
| 예시2 | 전남 해남 | 고구마, 배추 |
| 예시3 | 제주 서귀포 | 감귤, 당근(수확 예정) |
| 예시4 | 충남 홍성 | 토마토 |
| 예시5 | 강원 평창 | 감자 |
| 예시6 | 전북 완주 | 딸기 |
| 예시7 | 경남 밀양 | 풋고추 |
| 예시8 | 충북 충주 | 복숭아(수확 예정) |
| 예시9 | 경기 양평 | 청상추 |
| 예시10 | 전남 나주 | 배 |

- 전체 13개, 채소 7개·과일 6개. 사진 대신 품목별 예시 일러스트를 사용한다.
- 예시4 토마토 1개 + 예시10 배 1개: 상품 48,000원 + 배송비 7,500원 = 55,500원. 예시10 배 3개는 해당 농부 무료배송 기준을 충족한다.
- `node farmer-market/verify.cjs`: 농부 10명 모두 상품 존재, 상품 ID 중복 없음, 상품의 농부 연결·소개 작물 일치, 기존·신규 농부 계산과 품절 제한 확인.
- 상품에 연결된 예시1~10은 소개 삭제 대신 비공개를 사용한다. 새 소개를 추가하는 것만으로 판매 상품이 자동 등록되지는 않는다.
- 현재 목록은 예시 판매 구성이다. 실제 계절별 공급 가능 여부·가격·인증·재고·출고 일정은 운영 자료 확인 후 반영한다.

### 예시1~예시10 구성 (2026-11-10)

- 기본 소개 데이터를 공개 상태의 예시1~예시10으로 변경했다. 농장명과 지역·대표 작물·소개는 모두 화면 시험용이다.
- 농부 소개는 첫 페이지 9곳, 두 번째 페이지 예시10을 표시한다. 홈은 3곳씩 총 4페이지이며, 관리 목록도 전체 10곳을 표시한다.
- 이전 3개 기본 예시가 수정되지 않은 경우에만 자동 전환한다. 사용자가 등록하거나 수정한 자료는 보존한다.
- 상품 연결을 위해 첫 3개 농부의 ID는 유지했다. 이후 장터 확장에서 예시1~10의 소개 기본값과 상품·배송용 농부 이름을 공통 데이터로 통일했다. 운영자가 직접 수정한 소개 데이터의 서버 통합은 후속 단계에서 진행한다.
- `verify-farmers.cjs`는 10개 기본값, 9+1 페이지, 추가 등록 후 30개 확장, 기존 데이터 자동 전환과 직접 수정한 자료 보존을 검증한다.

### 농부 소개·관리 확장 (2026-11-10)

- [농부 전체 목록](http://127.0.0.1:4175/#farmers): 공개된 농부를 9곳씩 표시하고 등록 수에 따라 페이지를 생성한다. 농장명·농부 이름·지역·작물 검색을 제공한다.
- 홈은 3곳으로 총수를 제한하지 않고 공개 농부 전체를 3곳씩 넘겨본다. 전체 목록과 개별 소개·판매 상품으로 연결된다.
- [농부 소개 관리](http://127.0.0.1:4175/#manage-farmers): 등록·수정·공개/비공개·표시 순서·사진 등록·검색·상태 필터·페이지 이동을 제공한다. 화면 상단의 ‘농부 소개 관리’로 진입한다.
- 필드: 농장명·농부 이름·지역·대표 작물·소개·사진·표시 순서·공개 여부·예시 여부. 사진은 JPG/PNG/WebP 1MB 이하이며 브라우저 저장 용량을 넘으면 오류를 표시하고 입력값을 유지한다.
- 소개 데이터는 이 브라우저에 저장한다. 소개 수정은 기존 상품명·배송비 등 판매 데이터를 변경하지 않는다. 실제 운영에서는 동일 농부 ID를 서버 데이터로 연결할 예정이다.
- 기존 판매 상품과 연결된 예시 농장은 삭제를 막고 비공개 전환을 제공한다. 새 소개는 두 번의 삭제 확인 동작 후 삭제할 수 있다. 비공개는 소개 목록·상세만 숨기며 상품 판매 중지를 의미하지 않는다.
- 관리자 인증은 미연결이다. 실제 서비스의 권한 보호가 있는 운영자 화면이 아닌 로컬 시연 기능이다. 다른 브라우저·기기로 공유되지 않고 저장소 삭제 시 자료가 사라진다.
- `node farmer-market/verify-farmers.cjs`: 23개 등록, 페이지 분할, 검색·표시 순서, 비공개 제외, 새로 읽기, 삭제 보호, 입력·사진 형식 검사, 손상된 저장 데이터·저장 실패·빈 목록 처리 통과.
- 브라우저 확인: 4번째 농부 등록→상세 표시→홈 2페이지→비공개→새로고침 후 유지→공개 검색 제외→소개 수정 저장→테스트 자료 삭제. 기존 농부의 판매 상품 연결과 360px 관리 화면의 가로 넘침 없음 확인.
