# 청년농부 장터 웹앱

청년 농부의 제철 농산물을 소개하고 판매하는 웹앱의 개발 프로젝트입니다. 현재 회원 인증을 연결한 로컬 개발 단계입니다.

## 빠른 실행

Node.js **24.22.1 이상 24.x** 환경에서 저장소 루트에서 실행합니다. 외부 패키지 설치는 필요하지 않습니다.

```sh
node farmer-market/server.cjs --dev-mailbox
```

브라우저에서 [http://127.0.0.1:4175](http://127.0.0.1:4175)를 엽니다. 회원가입 후 **로컬 테스트 수신함**의 이메일 확인 링크를 누르면 로그인할 수 있습니다. 실제 메일은 보내지 않습니다. 개발용 수신함을 끄려면 `--dev-mailbox` 없이 실행합니다.

```sh
node farmer-market/verify-all.cjs
```

현재 가능: 농부 10명·상품 13개의 탐색/검색/페이징, 농부별 장바구니 계산, 회원가입·이메일 확인·로그인·로그아웃·비밀번호 재설정. 실제 주문·결제·배송 연동과 운영 배포는 아직 없습니다. HTTP 개발 쿠키와 테스트 수신함은 외부 공개 운영용 구성이 아닙니다.

## 2. 인터뷰 전체 기록

처음 요청은 홈페이지 기획 전문가 역할로, 목적부터 한 번에 질문 하나씩 최대 10개를 진행해 방문 대상·소개 내용·메뉴·기능을 구체화하고 기획안을 정리하는 것이었다. 당시 디자인·코드 제작은 금지했다. 이후 사용자가 별도로 디자인 가이드와 이미지 미리보기를 요청하면서 디자인 작업 범위는 확대됐고, 코드 금지는 계속 유지됐다.

| 순번 | 질문 주제와 제시된 선택지 | 최종 답변·상태 |
|---|---|---|
| 1 | 목적: 직접 판매 / 농부·수확물 소개 / 정기 고객 확보 | **수확물 직접 판매** 확정 |
| 2 | 고객: 일반 가정 / 식당·카페 / 개인과 사업자 모두 | **개인과 사업자 모두** 확정 |
| 3 | 상품: 제철 채소·과일 / 대표 한 품목 / 농산물·가공식품 | **제철 채소·과일** 확정 |
| 4 | 배송: 농부별 개별 배송 / 합배송 / 지역 배송·방문 수령 | **농부별 개별 배송** 확정 |
| 5 | 사업자 구매: 별도 견적 / 전용 가격 즉시 주문 / 개인과 동일 | **별도 견적 문의** 확정 |
| 6 | 소개: 농부·재배 이야기 / 품질·생산 정보 / 공동체 가치 | **모두** 확정 |
| 7 | 메뉴: 판매·소개 균형형 / 쇼핑 중심형 / 콘텐츠 강화형 | **판매·소개 균형형** 확정 |
| 8 | 주문·결제: 비회원·회원 모두 / 회원만 / 주문 후 계좌이체 | **비회원·회원 모두 구매**, 장바구니·온라인 결제·배송조회 확정 |

### 재질문과 결정 경위

- 첫 추가 기능 답변은 후기·상품 문의였다. 운영 담당 질문 중 사용자가 앞 질문을 다시 요청했다.
- 다시 나온 추가 기능 질문에 “12”라고 답했고, 당시 기획안은 1·2번 모두라는 가정으로 정리했다. 운영 담당은 답을 받지 못해 통합 관리를 가정했다. 이때의 가정은 이후 명시 답변으로 대체됐다.
- 사용자가 마지막 두 질문을 다시 요청했고, 추가 기능에서 **“두 기능 모두”**를 명시적으로 선택했다.
- 운영 담당 재질문에서 사용자는 통합 관리에 농부에게 주문을 전달하는 기능도 포함되는지 물었다. 운영자가 내려받아 직접 전달하는 기본 방식과 자동 전달 방식의 차이를 설명했다.
- 사용자는 자동 전달과 3번 분담 방식의 차이를 물었다. **자동 전달은 주문 전달 방법, 분담은 상품·재고·운송장 등을 누가 직접 관리하는지의 차이**라고 설명했다. 3번에도 자동 알림은 추가할 수 있다고 안내했다.
- 최종 답변은 **“1번에 자동전달”**이었다. 따라서 통합 관리만 가정한 초기안이나 수동 전달 기본안, 농부가 직접 관리 화면을 사용하는 분담안으로 되돌리지 않는다.

## 3. 목적·방문 대상·상품

### 사용자 확정

- 청년 농부들이 공동으로 수확물을 직접 판매하는 홈페이지를 만든다.
- 일반 가정의 개인 소비자와 식당·카페 사업자 모두를 대상으로 한다.
- 초기 판매 대상은 여러 농부의 제철 채소·과일이다.
- 농부와 재배 이야기, 품질과 생산 정보, 공동체의 가치를 모두 소개한다. 어느 하나만 강조하는 것으로 축소하지 않는다.

### 기획안에 포함된 방향

- 농부와 생산 정보를 투명하게 알려 신뢰와 재구매를 높인다.
- 개인은 가정용 소량 구매, 사업자는 대량 공급 견적 문의를 중심으로 이용한다.
- 초기 단품 판매·국내 배송을 기본 범위로 제안했다. 국내 배송 한정과 단품 구성은 사용자가 별도로 세부 확정한 것은 아니다.
- 구매 전환율·재구매율·사업자 견적 문의 건수를 성과 지표로 제안했다. 목표 수치·측정 방법은 미확정이다.
- 정기배송과 사업자 전용 가격은 추후 확장 항목으로 제안했다. 가공식품·합배송·방문 수령은 이번 인터뷰에서 초기 선택되지 않았다.

## 4. 메뉴와 콘텐츠

확정한 기본 메뉴는 **제철 장터 / 농부 소개 / 우리의 이야기 / 사업자 대량구매 / 고객센터**다. 장바구니·주문조회·마이페이지는 별도 이용 메뉴로 계획했다.

| 메뉴 | 포함할 내용 |
|---|---|
| 제철 장터 | 채소·과일 목록, 품목·농부별 검색과 필터, 상품 상세 |
| 농부 소개 | 얼굴·농장 사진, 농장 위치, 농사를 시작한 계기, 대표 작물, 재배 방식·과정 |
| 우리의 이야기 | 공동체 설립 취지와 가치, 청년 농부들의 협업 이유, 지역 농업 활동, 재배·수확 이야기 |
| 사업자 대량구매 | 공급 안내, 희망 조건을 받는 견적 문의 양식 |
| 고객센터 | 공지사항, 자주 묻는 질문, 배송·교환·환불 안내, 고객 문의 |

상품 상세는 상품명, 가격, 중량·규격, 원산지, 생산 농부, 수확 시기·발송 예정일, 보관법, 배송비, 확인 가능한 재배·인증 정보로 구성한다. 인증은 실제 보유한 경우에만 표시한다. 당일 수확·무농약·최저가 등 확인되지 않은 주장은 사용하지 않는다.

## 5. 고객 기능과 구매 흐름

### 개인 구매

**상품 선택 → 장바구니 → 농부별 배송비 확인 → 온라인 결제 → 주문·배송 조회**가 기본 흐름이다.

- 회원·비회원 모두 구매할 수 있다.
- 비회원은 주문번호와 본인 확인을 통해 주문을 조회하는 방식으로 계획했다. 구체적인 인증 수단은 미확정이다.
- 상품 상세 구매 영역에 옵션·수량·합계, 장바구니 담기·바로 구매를 배치한다.
- 품절은 구매를 제한하고 재입고 알림 신청을 제공한다. 수확 예정 상품은 판매 시작 알림과 구분한다.

### 농부별 개별 배송

- 각 농부가 자신의 농장에서 포장·발송한다. 여러 농부 상품을 한곳에서 합배송하는 운영이 아니다.
- 장바구니·결제는 농부별 묶음으로 상품, 상품 금액, 배송비, 발송 예정일을 보여준다.
- 결제 전에 농부별 배송비와 배송비 합계·전체 결제 금액을 확인하게 한다.
- 주문조회는 농부별 발송 상태·운송장을 구분한다. 배송 일정이 서로 다를 수 있음을 알린다.
- 정확한 배송비, 무료배송 조건, 도서산간 비용, 택배사, 출고 마감·소요일, 반품 조건은 미확정이다.

### 사업자 견적 문의

- 사업자는 전용 가격으로 바로 결제하기보다 별도 견적을 요청한다.
- 기획안 양식: 업체명, 담당자 연락처, 희망 품목·수량·납기·배송지.
- 공동 운영자가 공급 가능 여부와 가격을 회신한다.
- 접수 완료와 견적 확정은 구분한다. 응답 기한·최소 주문량·지속 공급 조건은 미확정이다.

### 후기·상품 문의와 알림

- **후기·상품 문의와 재입고·수확 알림 모두 초기 기능**이다.
- 구매 완료 고객이 후기를 쓰고, 상품별 질문·답변을 제공하는 방식으로 계획했다.
- 재입고와 다음 수확물 판매 시작 소식을 상품별로 신청받는다.
- 가이드는 구매 여부 표시, 문의 유형·답변 상태, 개인정보 비공개, 신청·해지 결과 안내를 제안한다.
- 고객 알림의 수신 채널·발송 조건·회원 및 비회원별 신청 방식·동의 정책, 후기 수정·삭제 및 문의 공개 범위는 미확정이다.

## 6. 운영과 주문 자동 전달

### 확정한 업무 분담

| 업무 | 공동 운영자 | 각 농부 |
|---|---|---|
| 상품 등록·수정 | 직접 관리 | 상품 정보를 운영자에게 전달 |
| 재고 반영 | 전달받은 정보를 홈페이지에 반영 | 실제 재고·변동을 운영자에게 전달 |
| 주문 관리 | 전체 주문을 통합 관리 | 자신의 발송 대상 주문을 자동으로 전달받음 |
| 포장·발송 | 진행 상황 관리 | 직접 수행 |
| 운송장 등록 | 농부에게 받아 입력 | 운송장 정보를 운영자에게 전달 |
| 콘텐츠·고객센터·대량구매 문의 | 통합 관리 | 필요 시 생산·공급 정보 제공 |

초기에는 농부가 직접 상품·재고·운송장을 관리하는 별도 관리 화면을 만들지 않는 것으로 계획했다. 통합 관리와 자동 전달을 선택했다는 이유로 농부에게 직접 사이트 관리 업무를 추가하지 않는다.

### 기획안에 포함된 자동 전달 동작

- 결제 완료 시 해당 농부에게 자신의 상품 주문만 자동 전달한다.
- 전달 항목: 주문번호, 농부명, 상품·수량, 수령인·배송지·연락처, 배송 요청사항 등 발송에 필요한 정보.
- 공동 운영자는 농부별 주문·전달 상태를 확인하고 실패 시 재전송한다.
- 전달 후 주문 취소·변경이 생기면 해당 농부에게 변경 알림을 전달한다.
- 전달 성공·실제 발송 완료·결제 상태를 별도로 구분한다. 고객에게 내부 전달 상태를 노출하지 않는다.
- 고객 개인정보는 해당 주문 발송 담당 농부에게 필요한 범위로 제공한다.
- 농부별 주문 내역과 정산 내역을 구분해 관리하는 항목도 초기 기획안에 포함됐다. 정산 계산·수수료·주기·지급 방식은 미확정이다.

**전달 채널 상태:** 초기 이메일 전달과 농부별 수신 주소 등록은 이전 기획안·design.md의 제안 기본값이다. 사용자가 확정한 것은 자동 전달 방식이며, 이메일이라는 채널을 직접 선택한 것은 아니다. 이메일·문자·메신저 중 실제 채널, 외부 서비스, 실패 재시도와 수신 확인 방식은 추가 결정이 필요하다. 고객의 재입고·수확 알림 채널과도 별도로 결정한다.

## 7. 디자인 가이드와 첫 화면 구성

### 가이드의 방향

- 콘셉트: **농부의 얼굴이 보이는, 따뜻하고 정돈된 제철 장터**.
- 크림색 바탕·짙은 초록색 중심에 연두·밀색 이야기 구획을 사용한다.
- 한글에 적합한 Pretendard와 대체 글꼴을 사용한다.
- 실제 농산물·농부·농장 사진과 명확한 구매 정보를 중심으로 구성한다.
- 참고 디자인의 큰 제목·여백·색면 구획은 응용하되 Figma의 전용 글꼴·브랜드 색 조합·콜라주·섹션 배열을 복제하지 않는다.
- 수치와 팔레트는 design.md에서 제시한 가이드 값이다. 사용자가 모든 세부 수치를 개별 승인한 것으로 보지 않는다.

### 전체 배치

1. 헤더: 로고, 확정 기본 메뉴, 검색·장바구니·회원 메뉴.
2. 첫 소개: 제목·짧은 설명·제철 수확물 보기 버튼과 수확 사진. 모바일은 문구 다음 사진.
3. 제철 장터: 4~8개 상품 미리보기, 전체 보기, 채소·과일 필터.
4. 농부 소개: 연두 구획, 농부 사진·이름·지역·짧은 이야기·소개 링크.
5. 우리의 이야기: 크림 바탕, 공동 작업 사진과 협업 이야기.
6. 사업자 대량구매: 밀색 구획, 공급 안내와 문의 버튼.
7. 고객 안내: 수정 시안에는 농부별 개별 배송 / 주문·배송 조회 / 자주 묻는 질문 안내 줄이 포함됐다.
8. 푸터: 고객센터, 배송·반품 안내, 운영 주체와 필수 사업자 정보, 약관·개인정보 안내.

이미지 시안은 대표 홈페이지를 위에서 아래까지 보여주는 미리보기다. 상품 상세·결제·관리자 등 전체 하위 화면을 모두 제작한 것은 아니다. 자동 전환 배너와 움직이는 띠 광고는 가이드의 초기 구성에서 제외했다.

- **2026-11-10 / 4단계 회원 인증:** [구현·시험 안내](docs/04-auth-implementation.md)에 따라 회원가입·이메일 확인·로그인·로그아웃·비밀번호 재설정·내 계정과 로컬 테스트 수신함을 구현했다. 회원·해시·동의 기록·세션·토큰은 SQLite에 저장한다. Host/Origin·CSRF·입력 크기·시도 횟수·토큰 1회 사용·세션 만료를 적용하고, 일반 회원의 운영자 접근을 차단했다. 운영자 승격은 기존 확인 완료 계정에 대한 로컬 CLI로만 제공하며 임의 관리자 계정은 만들지 않았다.

### 구현 시 유지할 기준

- **주문 하나에 농부별 배송 묶음을 둔다.** 결제는 함께 진행하더라도 배송비·발송 상태·운송장은 농부별로 관리한다.
- **결제 상태·농부 전달 상태·배송 상태를 구분한다.** 전달 성공이 발송 완료로 표시되지 않게 한다.
- **농부 전용 관리 화면은 초기 범위에 넣지 않는다.** 운영자가 통합 관리하고 농부는 주문을 자동 전달받는다.
- **후기·상품 문의·재입고·수확 알림은 모두 초기 오픈 범위다.** 개발 순서가 뒤여도 추후 기능으로 제외하지 않는다.
- **최신 디자인 수정 사항을 적용한다.** 반복되는 세 가닥 강조 장식은 전체에서 제거하고, 얇은 선과 작은 라벨을 기준으로 구성한다.

### 첫 착수 작업과 일정 산정

우선 **1단계의 미확정 사항을 결정 항목으로 정리하면서 2단계의 화면 목록을 작성**한다. 기술 스택·외부 서비스·실제 자료가 미정이므로, 개발 일정과 비용은 해당 범위가 정해진 후 산정한다. 이 섹션 추가 자체는 코드 작성·외부 서비스 연결·실제 결제·메시지 발송·배포를 수행한다는 의미가 아니다.

## 12. 부록: 기존 design.md 전체 보존

## 6. 레이아웃과 반응형 기준

- 콘텐츠 최대 폭: 1200px, 중앙 정렬.
- 화면 구분: 데스크톱 1024px 이상, 태블릿 768~1023px, 모바일 767px 이하.
- 좌우 여백: 데스크톱 40px, 태블릿 24px, 모바일 16px.
- 구획 간 간격: 데스크톱 80px, 태블릿 64px, 모바일 48px.
- 기본 간격 단위: 4 / 8 / 12 / 16 / 24 / 32 / 48px.
- 상품 목록: 데스크톱 4열, 태블릿 3열, 모바일 2열. 카드 간격은 각각 24 / 20 / 12px.
- 카드 제목은 최대 2줄 표시하되 상세 화면에서는 전체 이름을 제공한다. 가격·규격·배송비는 잘리지 않게 별도 행으로 둔다.
- 상세 화면: 데스크톱 사진·구매 정보 2열, 태블릿과 모바일은 사진 다음 구매 정보 순서의 1열.

- 본문은 한 줄 약 35~45자 범위로 유지해 넓은 화면에서도 긴 문단을 읽기 쉽게 한다.

데스크톱 헤더는 로고, 기본 메뉴, 검색·장바구니·회원 메뉴를 배치한다. 1024px 미만에서는 로고, 검색, 장바구니, 메뉴 버튼으로 줄인다. 모바일 상품 필터는 가로 스크롤을 허용하지만 페이지 전체에 가로 스크롤이 생기지 않게 한다.

4. **농부 소개:** 연두색 구획에 농부 사진, 이름·지역·짧은 이야기, “농부 만나보기”.
5. **우리의 이야기:** 크림 바탕에 협업 활동과 농장 사진을 배치한다.
6. **사업자 대량구매:** 밀색 패널에 공급 안내와 “대량구매 문의하기”.
7. **푸터:** 고객센터, 배송·반품 안내, 운영 주체와 필수 사업자 정보, 이용약관·개인정보 안내.

### 장터와 상품 상세

상품 카드 순서는 사진 → 농부·지역 → 상품명 → 중량·규격 → 가격 → 배송비·발송 안내다. 상태 라벨은 “판매 중”, “품절”, “수확 예정”처럼 구체적으로 표시한다.

상품 상세는 사진, 구매 정보, 생산·수확 정보, 농부 소개, 배송·교환 안내, 후기·상품 문의 순서로 구성한다. 구매 영역에는 옵션·수량·합계와 “장바구니 담기”, “바로 구매”를 둔다. 품절일 때는 구매 버튼을 비활성화하고 “재입고 알림 신청”을 제공한다. 수확 예정 상품에는 판매 시작 알림을 구분해 표시한다.

### 장바구니·결제·주문조회

농부별로 주문을 묶어 농장명, 상품, 상품 금액, 배송비, 발송 예정일을 표시한다. 전체 합계와 배송비 합계를 결제 전에 보여준다. 여러 농부의 상품이 각각 배송된다는 안내를 주문 요약 가까이에 둔다.

회원·비회원 구매 진입을 모두 명확히 제공한다. 주문조회에서는 농부별 발송 상태와 운송장을 나누어 표시한다. “한 번에 도착”하는 것으로 오해할 표현은 사용하지 않는다.

### 소개·문의·알림

- 농부 소개는 얼굴·농장 사진과 지역·대표 작물·재배 이야기를 함께 보여준다. 인증은 확인된 정보만 표시한다.
- 사업자 문의는 업체명, 담당자 연락처, 품목·수량, 희망 납기, 배송지로 구성한다. 접수 완료 화면은 견적이 확정되었다고 표현하지 않는다.
- 후기에는 구매 여부를 식별하고, 상품 문의에는 문의 유형과 답변 상태를 표시한다. 공개 화면에 연락처·주소가 노출되지 않게 한다.
- 알림 신청에는 대상 상품, 알림 종류, 수신 채널과 동의 내용을 표시한다. 신청·해지 결과를 문구로 안내한다. 수신 채널은 실제 제공 가능한 방식이 확정되면 화면에 반영한다.

## 8. 버튼·카드·폼 스타일

| 요소 | 형태와 상태 |
|---|---|
| 주요 버튼 | 초록 바탕·흰 글자, 높이 48px 이상, 좌우 여백 24px, 모서리 12px. “바로 구매”, “결제하기”, “문의 접수하기”에 사용 |
| 보조 버튼 | 흰 바탕·초록 글자·초록 테두리, 높이 48px, 모서리 12px. 장바구니·알림 신청에 사용 |
| 필터 | 높이 44px 이상, 알약형. 선택 시 초록 바탕·흰 글자와 선택 상태 표시 |
| 텍스트 링크 | 초록 글자, 본문 안에서는 밑줄로 식별. “전체 보기” 등 탐색에 사용 |
| 아이콘 버튼 | 44×44px 이상 터치 영역. 검색·장바구니 등 의미를 접근성 이름으로 제공 |
| 상품 카드 | 흰 바탕, 얇은 일반 경계, 모서리 16px, 정보 영역 여백 16px. 모바일 12px |
| 입력 필드 | 흰 바탕, 입력 경계색 1px, 높이 48px 이상, 모서리 8px, 글자 16px |
| 상태 라벨 | 12~14px, 충분한 내부 여백. 색과 상태 문구를 함께 제공 |

한 행동 영역에서 주요 버튼은 하나를 중심으로 둔다. 구매 버튼과 알림 버튼이 같은 중요도로 경쟁하지 않게 한다. 입력 항목에는 항상 보이는 라벨을 붙이고, 필수 여부·예시·오류를 가까이 표시한다. 오류 발생 시 입력값은 유지한다.

키보드 초점은 2px 초록 외곽선과 2px 간격으로 표시하고 어두운 배경에서는 밝은 외곽선을 사용한다. 선택 상태는 체크 또는 텍스트로도 구분한다. 처리 중 버튼은 “결제 처리 중…”처럼 상태를 설명하고 중복 입력을 막는다.

카드 호버는 경계색 변화 정도로 제한한다. 메뉴·팝업만 약한 그림자를 사용한다. 전환은 150~200ms 이내를 기준으로 하며 움직임 줄이기 설정을 존중한다.

## 9. 사진·이미지 스타일

- **상품 사진:** 실제 판매 농산물, 자연광, 담백한 배경. 카드 비율은 1:1로 통일한다. 대표 사진은 전체 형태, 추가 사진은 질감·크기·포장 상태를 보여준다.
- **농부 사진:** 눈높이에서 촬영한 자연스러운 작업 장면. 인물·손·도구·작물이 함께 보여 생산 현장을 이해할 수 있게 한다. 기본 비율은 4:5다.
- **농장·공동체 사진:** 밭, 수확, 함께 포장하는 장면 등 실제 활동을 보여준다. 기본 비율은 3:2다.
- **첫 소개 사진:** 데스크톱 4:3, 모바일 4:3 비율을 기본으로 하고 핵심 피사체가 잘리지 않게 초점을 조정한다.
- **보정:** 따뜻한 중립 톤을 유지한다. 실제 상품의 색·크기·신선도를 과장하는 보정과 강한 필터는 피한다.
- **장식:** 단순한 선 아이콘을 사용하고 잎사귀·손그림 장식은 소량만 쓴다. 가격·규격·배송 안내 위에 겹치지 않는다.

사진 위에 가격이나 긴 문장을 올리지 않는다. 상품 사진은 실제 판매 상품으로 준비하며, 자료가 없으면 대체 이미지임을 명확히 표시한다. 농부·농장 이미지는 사용 허락을 확인한다. 의미 있는 사진에는 내용에 맞는 대체 텍스트를 제공하고, 장식 이미지는 읽기 흐름에서 제외한다.

## 10. 공동 운영자 화면과 자동 주문 전달

운영 방식은 **공동 운영자 통합 관리 + 농부에게 주문 자동 전달**이다. 농부용 상품·재고 관리 화면은 초기 범위에 포함하지 않는다.

- 운영자 화면은 동일한 글꼴·색상 체계를 사용하되 큰 사진·장식 패널보다 검색, 상태 필터, 표 중심으로 구성한다.
- 주문 목록에 주문번호, 농부, 결제 상태, 발송 상태, 전달 상태를 구분한다. 자동 전달 성공과 실제 발송 완료를 같은 상태로 표현하지 않는다.
- 전달 실패는 문구·아이콘으로 강조하고 재전송 동작을 제공한다. 취소·변경 주문은 변경 내용을 쉽게 찾을 수 있게 한다.
- 초기 이메일 전달 양식은 농부명, 주문번호, 상품·수량, 발송에 필요한 고객 정보, 배송 요청사항을 읽기 쉬운 표로 정리한다. 해당 농부의 상품만 포함한다.
- 운영자가 운송장과 재고 정보를 반영하는 업무를 쉽게 찾게 하고, 고객 배송조회에는 내부 전달 상태를 노출하지 않는다.

## 11. 디자인 검수 기준

- 360px 모바일과 768px·1280px 화면에서 상품명·가격·배송비가 겹치거나 잘리지 않는다.
- 첫 화면에서 판매 상품과 구매 진입점을 쉽게 찾을 수 있다.
- 여러 농부의 상품 주문 시 개별 배송과 배송비 합계를 결제 전에 이해할 수 있다.
- 한글 본문은 기본 16px이며 작은 안내문도 충분한 대비를 확보한다.
- 일반 텍스트 대비는 4.5:1 이상, 큰 글자는 3:1 이상, 필수 UI 경계·상태 표시는 3:1 이상을 기준으로 실제 조합을 검수한다.
- 버튼과 아이콘의 터치 영역은 44px 이상이고 키보드 초점이 보인다.
- 모바일 하단 고정 구매 영역을 적용할 경우 마지막 콘텐츠와 초점 요소를 가리지 않는다.
- 상품 로딩·검색 결과 없음·품절·오류·문의 접수 완료 상태에도 다음 행동을 안내한다.
- 사진 로딩 전에도 비율을 확보해 레이아웃 이동을 줄이고 첫 화면 밖 이미지는 지연 로딩한다.
- 참고 문서의 브랜드 색상·전용 글꼴·그래픽·배치를 그대로 복제하지 않았는지 확인한다.

## 12. 제작 시 준비할 자료

서비스명·로고, 농부별 소개와 사진, 실제 상품 사진, 규격·가격·원산지, 수확·배송 일정, 농부별 배송비, 운영자 연락처, 배송·교환 정책이 필요하다. 미확정 정보는 사실처럼 채우지 않고 확인 대상으로 표시한다.

이 가이드의 색상·글자 크기·간격은 본 프로젝트를 위한 제안값이다. 이후 실제 콘텐츠를 넣은 화면에서 가독성과 구매 흐름을 검수해 조정한다.
