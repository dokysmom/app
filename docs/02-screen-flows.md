# 2단계: 화면·사용 흐름 설계

작성일: 2026-11-10

기준 문서: [1단계 요구사항](01-requirements.md), [README](../README.md), [디자인 가이드](../design.md). 이번 산출물은 화면 설계와 로컬 탐색 프로토타입이다. 서버 인증·DB·결제·이메일 연동은 후속 단계에서 구현한다.

## 1. 목표와 구현 범위

- 고객·운영자 화면과 요구사항 F01~F16의 대응을 정의한다.
- 농부별 배송·합계를 결제 전에 확인하는 흐름을 설계한다.
- 홈→장터→상품 상세→장바구니→주문서의 연결을 로컬에서 시험한다.
- 실제 자료가 없는 상품·농장·이미지·가격은 예시로 표시한다.
- 품절·수확 예정·빈 장바구니·검색 결과 없음 상태를 제공한다.

## 3. 주요 이용 흐름

### 고객 구매

1. 홈 또는 장터에서 분류·농부·검색어로 상품을 찾는다.
2. 상세에서 규격·가격·발송 예정·농부별 배송비를 확인한다.
3. 판매 중 상품은 유효 수량을 선택해 담는다. 품절·수확 예정은 구매를 막고 알림으로 안내한다.
4. 장바구니에서 농부별 묶음과 배송비 합계를 확인하고 수량·삭제를 조정한다.
5. 주문서에서 회원·비회원 경로를 선택한다.
6. 후속 구현: 주문자·주소 입력→서버 가격/재고/주소 검증→필수 안내 확인→PG 결제→서버 결제 검증→주문 확정.
7. 후속 구현: 고객은 농부별 발송·운송장을 확인하며, 비회원은 이메일 확인 후 조회한다.

프로토타입의 ‘바로 구매 미리보기’는 상품을 장바구니에 담고 합계를 확인하도록 이동한다. 실제 단건 바로 구매는 주문 API 설계 시 별도 장바구니 처리 여부를 정의한다.

### 알림·문의

- 알림: 상품 선택→재입고/수확 종류 확인→이메일 확인→신청 완료→판매 회차 1회 발송→종료. 해지는 상품별 링크로 처리한다.
- 견적: 공급 안내→업체/담당자/이메일/연락처/품목/수량/납기/배송지→동의→접수→운영자 검토→별도 회신. 접수 결과를 견적 확정으로 표시하지 않는다.
- 후기: 배송 완료 상품→본인 구매 확인→작성/수정/삭제. 문의: 본인 확인→비공개 기본 작성→운영자 답변→작성자 확인.

### 운영자·농부

1. 운영자는 농부·상품·배송 설정을 등록하고 필수 정보 확인 후 판매 상태로 전환한다.
2. 결제 검증 후 농부별 전달 작업을 생성한다. 이메일에는 해당 주문 확인용 보안 링크를 포함한다.
3. 전달 실패는 자동 재시도·운영자 재전송으로 처리한다. 성공은 이메일 서비스 접수 상태이며 출고 상태와 분리한다.
4. 농부는 자신의 발송 대상만 확인하고 운송장을 운영자에게 전달한다.
5. 운영자가 운송장을 반영하면 고객 배송조회에 표시한다.
6. 취소·변경·환불 처리는 이력을 보존하고 해당 농부에게 변경 알림을 전달한다.

## 4. 화면 배치와 반응형

| 화면 | 데스크톱 | 모바일 |
|---|---|---|
| 홈 | 문구/농장 일러스트 2열→상품 4열→농부→이야기→사업자→안내 | 문구→일러스트→상품 2열→소개 구획 1열 |
| 장터 | 제목→분류/농부/검색→상품 4열, 태블릿 3열 | 필터 줄바꿈·검색 전체 폭→상품 2열 |
| 상세 | 이미지/구매 정보 2열→생산 이야기 | 이미지→정보→수량·구매→이야기 |
| 장바구니 | 농부별 묶음/합계 패널 2열 | 묶음→합계 순서의 1열, 태블릿도 1열 |
| 주문서 | 입력 예정 영역/주문 요약 2열 | 구매 경로→정보 영역→배송 묶음→합계 |
| 관리자 | 검색/상태 필터→표→상세와 이력 | 표 핵심 열과 상세 화면으로 분리, 후속 구현 |

실제 사진이 준비되지 않아 코드로 작성한 예시 일러스트를 사용했다. 색상과 구획은 기존 가이드를 따르며 세 가닥 강조 장식은 사용하지 않았다. 현재 모바일 메뉴는 가로 스크롤 방식이며, 정식 UI 단계에서 메뉴 버튼 방식으로 다듬을 예정이다. 현재 화면이 최종 디자인 승인본을 의미하지 않는다.

## 5. 상태·입력·접근성 기준

- 로딩: 후속 API 연결 시 구획별 진행 상태와 재시도를 제공한다. 현재 데이터는 로컬 상수이므로 가짜 로딩을 넣지 않는다.
- 검색 없음: 조건 초기화 버튼. 빈 장바구니: 장터 이동 버튼. 잘못된 주소/상품: 홈 또는 장터 복귀 안내.
- 수량: 정수 1 이상·상품 재고 이하. 저장 데이터는 허용 상품·재고 상한으로 정규화한다.
- 품절/수확 예정: 구매 차단, 별도 알림 안내. 삭제 후 농부별 합계와 배송비를 즉시 재계산한다.
- 후속 입력 폼: 항상 보이는 라벨·필수 표시·필드별 오류·입력값 유지. 서버 오류 시 재시도와 중복 제출 방지.
- 키보드 초점 표시·페이지 이동 후 본문 초점·상태 알림·필터 선택 상태 제공.
- 실제 개인정보 입력·발송과 내부 관리자 상태의 고객 노출은 이번 미리보기에 포함하지 않는다.

## 6. 검증과 다음 단계

### 후속 반영: 농부 수 증가와 소개 관리

추가 반영: 제철 장터를 예시1~예시10과 각 농부의 취급 상품 총 13개로 연결했다. 목록 필터·상품 상세·농부별 수확물·장바구니·주문서에 동일 농부 ID와 기본 정보를 사용한다. 구성과 검증 기록은 [미리보기 안내](../farmer-market/README.md)를 따른다.

2026-11-10 사용자 요청에 따라 농부 소개를 등록 수에 따라 늘어나는 목록으로 확장했다.

| 화면 | 변경 사항 |
|---|---|
| 홈 S01 | 공개 농부 총수 표시, 3곳씩 페이지 이동, 전체 목록 링크 |
| 농부 목록 S06 `#farmers/{page}` | 9곳씩 페이지 이동, 농장명·농부 이름·지역·작물 검색, 빈 목록·검색 없음 |
| 농부 상세 `#farmer/{id}` | 사진·지역·이름·작물·소개·연결된 판매 상품, 비공개/미존재 접근 안내 |
| 소개 관리 `#manage-farmers` | 전체/공개/비공개 집계, 검색·상태 필터·페이지 이동, 공개 전환 |
| 등록·수정 `#new-farmer`, `#edit-farmer/{id}` | 입력 검증·사진·정렬 순서·공개 여부·저장·삭제 보호 |

이는 공동 운영자의 **농부 소개 관리** 기능이며 농부 본인이 사용하는 별도 관리 화면이 아니다. A02 전체 중 소개 관리 부분만 로컬로 구현한 상태다. 상품·배송·이메일 관리와 관리자 인증·DB 저장은 후속 구현 범위로 유지한다. 상세·목록은 비공개 소개를 표시하지 않지만 실제 권한 보안은 서버 연결 시 구현해야 한다.

계산 테스트와 실제 브라우저 검증 결과는 [미리보기 안내](../farmer-market/README.md)에 기록한다. 2단계 화면 설계 초안과 주요 탐색 프로토타입을 작성했으며, 전체 화면의 정식 구현·접근성 종합 검수·실서비스 검증은 완료하지 않았다.

다음은 **3단계: 기술·데이터 구조 설계**다. 회원/비회원 인증, 주문/농부별 배송 묶음, 재고 확보, 결제 검증, 비동기 이메일 작업과 권한을 데이터 및 API로 구체화한다. 실제 자료 준비는 병행한다.
